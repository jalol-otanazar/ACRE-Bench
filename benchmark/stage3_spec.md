# Stage 3: Adversarial Corpus Stress Pass

Stage 3 is the hard-mode pass of ACRE-Bench.

It is not meant to add more easy paraphrases. It is meant to expose the mistakes that show up when retrieval systems are already decent but still fail under pressure.

## What stage 3 targets

- near-duplicate retrieval traps
- false-premise questions phrased naturally
- corpus answers buried under extra instruction text
- translation-sensitive wording shifts
- list-order sensitivity
- source confusion between neighboring works
- multi-hop questions that need two or more passages
- ranking failures when the correct passage is not the most obvious one

## Stage 3 scale

The target output size is roughly:

- **600 to 900 questions** from the 50 curated seeds
- **additional adversarial negatives** mixed throughout
- **at least 20% refusal and unsupported-claim items**
- **at least 25% multi-hop or cross-work synthesis items**

## What changes from stage 2

Stage 2 expanded the seed bank with controlled paraphrases.

Stage 3 adds:

- longer question stems
- distracting clauses
- source lookalikes
- wrong-but-plausible work names
- explicit refusal traps
- mixed instruction styles
- list questions with extra phrasing that can break weak models

## Output

Stage 3 is generated by:

- `scripts/build_stage3.py`

That script reads:

- `benchmark/seed_questions.jsonl`
- `benchmark/stage2_questions.jsonl`

and emits:

- `benchmark/stage3_questions.jsonl`

## Why this stage exists

A model that passes stage 1 and stage 2 can still fail when:

- it grabs the first semantically similar chunk
- it answers from memory instead of the corpus
- it misses a refusal because the false premise is embedded in a longer question
- it gives a list that is right in spirit but wrong in order
- it confuses two Aristotle works that share the same technical term

Stage 3 is where those failures should become visible.
